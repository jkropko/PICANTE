## 1. Route

Registered route followed without deviation, in the strongest available form.
The roster is version-controlled, so the frame is pinned to a **commit SHA
rather than a date**:

    repository  https://github.com/codeforamerica/brigade-information
    commit      6c5654c7fd9b9f9f236fcf6687d91f422efec050
    file        organizations.json

Archived at the commit URL on 2026-09-24 (see `wayback.txt`), so the roster
survives the repository.

**Capture mechanics.** The clone was made inside `snapshots/CFA/`, the SHA
recorded to `commit.txt`, `organizations.json` copied out, and the clone's
`.git` directory removed. A nested git repository would not have been tracked
as ordinary files by the project repository, and a submodule would have left
the data outside it — neither acceptable for a frozen snapshot that must
survive independently of upstream. The SHA in `commit.txt` preserves the
provenance without the dependency; `capture_log.py` reads it from there.

## 2. A historical frame, and the only one that can do this job

Code for America **sunset the Brigade Network in June 2023**. This frame is
registered as historical precisely for that reason: it is the only source in
the register that supplies organizations which have closed, gone dormant, or
carried on independently after their network ended.

The register's decision not to gate on recent activity depends on this frame.
Organizational status — active, dormant, closed — is coded as a variable with a
date and a dated evidence artifact rather than used as a screening criterion,
because gating on activity would bias the sample toward survivors and make
claims about field dynamics impossible. Most of the dormant and closed records
in this study will come from here.

Expect a high closure rate, and treat it as a finding rather than as attrition.

## 3. Boundary: the location rule, decided before capture

Decided 2026-09-16 and recorded in `frames.json` under
`frames.CFA.boundary.location_rule`: **`drop_clearly_non_us`**.

Records whose location reads US, **and records whose location cannot be
determined from the roster's city string**, stay inside the frame. Only records
a location string positively identifies as non-US are dropped at enumeration.

The reasoning, in short: C2 is a human determination made at O4 from the
organization's own materials, and it exists because frame location metadata is
unreliable. The CTFG boundary already embodies this by retaining
country-missing records. Applying the same logic here keeps the registered
division of labour intact rather than letting a string match at enumeration
pre-empt a criterion assigned to a coder.

The cost is that the enumerated count will exceed the register's "~125 US (of
221)" estimate, which assumed a US filter at capture. That estimate predates
anyone parsing the city strings and is not a commitment; every boundary drop is
logged, and each retained undeterminable record costs one manual C2
determination at O4.

What it protects: a brigade with a messy or missing city string is likely a
small volunteer group with a thin web presence — the tier-2 organizations that
do the work without the field vocabulary, which the draw rule goes out of its
way to reach before sampling can stop.

The rule itself is unchanged by §3a below. What §3a changes is which field
the rule reads.

## 3a. Boundary: the location FIELD, decided at O3

Decided 2026-09-30, before any record was enumerated, screened or coded, and
recorded in `frames.json` under `_decisions.cfa_location_field`: the boundary
tests the roster's **structured `location.country` field**
(`columns.country = "location.country"`). The free-text `city` string is used
only where the country field is blank. `location_rule` stays
`drop_clearly_non_us`.

**Why.** The city string misreads. `us_location_guess` treats a two-letter
token as a US state abbreviation, and three Brazilian brigades give their city
as "<city>, PR" — Paraná — which it reads as Puerto Rico. They would have
passed the boundary as US. Four more non-US brigades carry city strings the
function cannot read at all and would have been retained as undeterminable.
The country field states each of these outright.

**Measured on the pinned file** (frames_io.py 1.1.0):

    boundary reads          kept   undeterminable retained
    city string only         129                         5
    country field            122                         0

The seven records kept under the city string and dropped under the country
field are all non-US by the frame's own country field: the three Paraná
brigades, two Canadian brigades, and two further Brazilian brigades. The
country field drops nothing the city string keeps. All seven would have failed
C2 at O4; the choice moves their exclusion from a coder's determination to the
boundary, where the drop log records it.

**Fallback.** Five brigades have no location object at all. For those the
boundary reads the city string; all five read US. Every kept record's `notes`
states which basis decided it (`country_field` or
`city_fallback_country_blank`), and the run manifest reports the counts.

**What this does not change.** The country field is the frame's own claim and
is **not C2**. Every kept record still receives a C2 determination at O4 from
the organization's own materials. Puerto Rico is recorded as USA by the frame
and is retained.

## 4. Tag vocabulary — CONFIRMED

Confirmed 2026-09-30 against the pinned file with
`enumerate_o3.py inspect --frame CFA`. The earlier rules were taken from the
register's prose and had not been checked against the file.

**Inventory.** 221 records; 220 carry a `tags` list; 19 distinct tags:

    181  Brigade                                      5  Partner
     96  Code for America                             4  Code for Poland
     93  Official                                     3  Fellowship
     18  Code for All                                 3  Code for All Affiliate
     18  OK Lab                                       3  partner
     13  Code for America Fiscally Sponsored Brigade  2  Brigade Collaboration
     10  Government                                   2  Code for Japan
      9  midwest                                      2  Code for Romania
      5  Code for America Partner Brigade             2  Project
                                                      1  Temporary

Matching is **exact** (case-insensitive), not substring. `Brigade` does not
match `Brigade Collaboration` or `Code for America Fiscally Sponsored Brigade`.

**Rules set in `frames.json`:**

    include_any        ["Brigade"]
    exclude_any        ["Code for All", "Government"]
    independence_tags  ["Official",
                        "Code for America Fiscally Sponsored Brigade",
                        "Code for America Partner Brigade"]

- `include_any` confirmed as is. 181 records carry `Brigade` exactly.
- `exclude_any` kept as is, and harmless. `Government` never co-occurs with
  `Brigade`. `Code for All` co-occurs with it on three records, all non-US by
  the country field, so the exclusion changes only the reason logged for them,
  not whether they leave. The German OK Labs, Code for Poland, Code for Japan
  and Code for Romania brigades are all tagged `Brigade`; they leave on
  location (§3a), not on tag, so no exclusion is needed for them.
- **`independence_tags` corrected.** The placeholder read
  `["Official", "Partner", "Fiscally Sponsored"]`. No tag `Fiscally Sponsored`
  exists, and `Partner` / `partner` never co-occur with `Brigade`, so under
  exact matching the fiscal-sponsorship status of every brigade would have
  been silently lost — and it is what routes a record to the Rule 1
  fiscal-sponsor clause (§6). The real tags are the long-form ones above.

**Result under the confirmed rules and §3a** (measured, frames_io.py 1.1.0):

    rows read                         221
    dropped, excluded tag              28
    dropped, no include tag            15
    dropped, location non-US           56
    kept                              122

    of the 122 kept:
      Official only                                        75
      Official + CfA Fiscally Sponsored Brigade            13
      Official + CfA Partner Brigade                        5
      no independence tag                                  29

The 28 + 15 tag drops are the 40 non-brigade records (18F, government
entities, Code for All members, partners, projects) plus the three
Code-for-All-tagged brigades. Code for America itself is among the
non-brigade records; it enters the pool as a Rule 2 operator, not from this
frame. Code for Charlottesville is among the 122 (author-conflicted; see
`../ACT/notes.txt` §3).

## 5. Expected overlap with ACT

ACT is the successor network to the sunset Brigade program. Several ACT
members are plausibly on this roster too — the two frames describe the same
tradition a few years apart.

Both are Block B, so these records do not enter the multi-frame subset used in
sensitivity check (f), which requires frames from two or more blocks. Their
multi-frame provenance is retained in the data.

Frame redundancy between them is reported per block as description and **is not
compared across blocks** as evidence of relative population size. The register
names this case explicitly: a successor network to a sunset one manufactures
overlap independently of field size.

One thing the overlap does support, and it is worth stating because it is a
finding rather than an artifact: an organization on the 2023 brigade roster
that is also a 2026 ACT member has survived its network's closure and rejoined
a successor. That is field dynamics, visible only because the register carries
a historical frame alongside a current one.

## 6. Downstream notes

- The roster carries `previous_names`, captured and retained. It is how a
  brigade that renamed itself after the sunset is recognised as the same
  organization at deduplication.
- Independence tags (`Official`, `Code for America Fiscally Sponsored
  Brigade`, `Code for America Partner Brigade`; §4) are recorded per record in
  `cfa_independence_tag`. A fiscally sponsored brigade
  engages the Rule 1 fiscal-sponsor clause: resolve to the sponsored project if
  the frame names it and it meets C1 independently, otherwise to the sponsor,
  recording the routing. Never enter both.
- City strings are inconsistent and are normalised for comparison only; the
  raw value is retained on every record.
